- Status: proposed
- Date: 2026-10-06
- Decided by: pending maintainer review (branch prompt/three-layer-rewrite)
- Context
  - prompt-structure.md v1 mixed three layers in one file: kernel legality, user completeness, agent action
  - Symptoms: 48-condition remedy matrix claimed exhaustive against 110 non-success screens, Rust engine code in a prompt file, thresholds redefined against cans/trust.md, banks existing only as code fences
  - Frozen constraints carried in: no new CLI noun or verb in v1, pointer is doc://prompt/{bank}/{slug}@v, prompt:// reserved pending action.md and interface.md amendment
- Decision
  - cans/*.md is SSOT: legality is checked against cans at author time, never invented or restated by a prompt
  - docs/ is user-facing completeness: full reference lives there, prompt slices end with a docs: pointer and never duplicate it
  - banks/ prompts are agent-facing action only: state, next action, bound, exit condition, one leaf per turn
  - Remedy matrix leaves the prompt layer: candidate extraction at docs/reference/errors.md, unverified until checked per-row against cans owners
  - Engine code leaves the prompt layer: implementation home is cans/assembly.md ownership, referenced not reproduced
  - Slide caps reconciled: doc read default 100 in cans/interface.md, global result ceiling 500 in cans/action.md; prompt leaves may request up to 500, never above it
  - No --section flag in v1: leaf selection rides doc outline node ids; if the kernel cannot address leaves that way, interface.md amendment is required first
- Alternatives considered
  - Keep v1 all-in-one file and add missing coverage rows — rejected: grows the agent layer into the bloat it exists to prevent
  - Prompts restate cans directly for completeness — rejected: cans is builder-facing SSOT, wholesale agent exposure recreates harness catalog injection
  - Invent --section and sys verify now and legalise later — rejected: prompt files cannot legalise surface; blocked entries stay blocked
- Consequences
  - forensics and hitl banks are present but blocked until illegal screen states are legalised or renamed (wireframe P0-2) — resolved by ADR-003: screens renamed, both banks now serve
  - docs/ completeness debt becomes explicit: missing docs: targets are listed in prompt-structure.md section 7, not silently inlined
  - Slice caps in bank frontmatter must be honest: cap covers rendered leaf size, ceiling 500
  - Branch carries no cans/*.md surface changes: any follow-up amendment (interface leaf addressing, state taxonomy) lands as its own ADR
- Amendment — pointer namespace split, trigger SSOT, wireframe quarantine (user ruling, 2026-10-07, branch arch/boundary-decoupling)
  - Context: `doc://` carried two audiences — human docs (`doc://refund-policy`) and agent banks (`doc://prompt/genesis/blank_world@1`); bank `docs:` fields carried raw repo paths as a third form. Trigger facts existed twice (11 bank frontmatters and 12 `_triggers.json` entries). The wireframe held copies: `manifest.json` domain registry (21 domains from `_states.json`), `wireframe-structure.md` §4 (all 223 screens), and a draft prompt-awareness spec freezing pointer form and token caps into the output contract
  - The frozen pointer constraint in this record is released. `prompt://{bank}/{slug}@{version}` addresses agent campaign banks only; `doc://` addresses human-facing docs only; banks reference completeness through `doc://` pointers, never bare repo paths. The amendment lands in `cans/action.md` (Pointer taxonomy) and `cans/interface.md` (Document path, Prompt envelope): `inspect` on `prompt://` returns the campaign envelope, `doc outline` / `doc read` on `prompt://` fetch one leaf. No new CLI noun, verb, or flag
  - `_triggers.json` is the sole trigger registry (screen, predicate, pointer, serve level, reason). Bank frontmatter carries identity, vars, sections, caps, `docs:`, and status — no `trigger:` block. `manifest.json` (prompt) is campaign inventory only
  - The wireframe output contract carries one generic slot — `trailer` (human) / `next_action` (JSON) — defined in `wireframe-structure.md` §6.1.1 and `manifest.json` `output_contract.trailer`. The payload shape is frozen deterministically in that manifest (`machine_schema`: `prompt`, `reason`, `serve`), so prompt engine and wireframe fixtures validate against one schema; the screen-to-trailer mapping stays only in `_triggers.json`, and a cross-layer runner check (triggers, `_flows.json`, §4 rows against fixture pairs) makes a renamed screen fail before serving breaks (tightened 2026-10-07: a fully opaque slot leaves the boundary untestable). The wireframe `manifest.json` carries no domain registry; `_states.json` is read directly. `wireframe-structure.md` §4 stays as a context index — one scannable surface a reader loads before drilling into fixture pairs; it indexes and never originates, every row resolves to one fixture pair, and the fixture wins any conflict (user ruling, 2026-10-07). Registry naming is normalized: `flows.json` is `_flows.json`; a leading underscore marks internal engine configuration and graph state (`_triggers.json`, `_states.json`, `_flows.json`), a clean `manifest.json` marks an externally consumable compiler artifact
  - Alternatives rejected: one scheme with a `doc://prompt/` sub-namespace (every consumer still branches on audience at the first segment); bank frontmatter as trigger registry with `_triggers.json` generated (the generation claim already existed with no generator — drift by construction); a prompt-specific wireframe slot (hard-codes one producer into every fixture and runner check); a separate ADR file for this amendment (user ruling, 2026-10-07: targeted edits to existing files, no new file)
  - Consequences: the unpushed branch `prompt/doc-pointer-docs-ref` (`d08af2c`) is abandoned, its `docs:` → `doc://` conversions absorbed here; `wireframe/prompt-awareness` (`b930cbc`, removed from the remote 2026-10-07) stays abandoned; `prompt-awareness-spec.md` is deleted, its generic remainder absorbed into `wireframe-structure.md` §6.1.1/§6.2. Any consumer resolving `doc://prompt/...` breaks — no kernel resolves either scheme today, so the break is confined to these files. This record's three-layer decision stands untouched
