  - Identity hierarchy
    - Identity chain
      - principal — human or root authority holder (e.g. user:root, partner:idp)
      - agent — registered harness instance (agt_7f3k)
      - subagent — thread/event-loop worker sharing parent PID; tracked via harness markers: see #Harness-environment-markers
      - session — temporary engagement scope (ses_a9)
      - op — single leaf execution in causal DAG
      - federated caller — external workspace identity formatted as ws:<name> (e.g. ws:crm); callee policy maps this to an internal :principal
    - Ephemeral swarm identity
      - node prefix — disposable containers mint transient IDs: agt_tmp_<uuid8>
      - heartbeat loop — spokes ping Hub every 5s; updates heartbeat_at in agents table: see artifacts/system-schema.yaml#agents
      - reaper eviction — Hub reaps nodes exceeding lease_ttl; marks status: expired and purges active leases: see artifacts/governance.yaml#topology
      - preemption yield: see #Concurrency-scope
      - zero-disk credential — spokes negotiate HMAC capability token in memory via CAPCLI_AGENT_TOKEN; zero filesystem key storage
    - Credential binding
      - capability token — kernel-minted HMAC session token bound to active _budget_frames
      - workspace pinning — active session and principal pinned to capcli/envs/<name>/workspace.db
      - implicit fork — divergent harness thread marker under same PID forces session fork: see budget.md#Cascade
      - session fork — child agents inherit scoped parent token via session fork
      - acting identity — --by declares machine agent identity for audit trails and token validation
      - beneficiary identity — --as declares target principal; bound directly to SQLite :principal for row-level security
      - principal typing — :principal resolves to the domain row key (e.g. numeric customer id); kernel maps the --as identity string to the domain key before view binding
      - identity generation — tokens and ids kernel-issued; self-declaration denied
      - tenant scope definition: see world.md#Dual-schema
      - tenant authorizer enforcement: see physics.md#Two-layer-enforcement
    - System agent registry
      - storage — agents system table in workspace.db
      - schema — id pk, name unique, harness, principal, status

      - management — sys agent register, list, revoke
      - kernel principals
        - scheduler — capcli-cron owns automated time triggers
        - webhooks — capcli-watch owns asynchronous provider dispatches
        - listener — capcli-serve owns synchronous endpoint requests
        - execution token — kernel mints an ephemeral HMAC session token bound to the executing system principal per _inbox task execution: see world.md#Inbox-lifecycle

      - federated peers — ws:<name> identities registered as agents; principal column holds the mapped internal :principal

  - Sessions and boundaries
    - Session lifecycle
      - dual-session architecture — harness session and kernel session are strictly decoupled:
        - harness session — cognitive transcript, context window, and conversation memory owned entirely by the LLM runner (Claude Code, Cursor, Codex)
        - kernel session — cryptographic budget frame, claim lease holder, and causal DAG boundary owned entirely by SQLite (_budget_frames, claims)
      - session slaving — kernel auto-binds its session ID to harness environment markers (CLAUDE_CODE_SESSION_ID, CODEX_THREAD_ID) via Phase 1 sniffing; manual session tracking by agents is prohibited
      - turn-zero orientation — every harness turn executes capcli run overview as step zero; injects a dense (<60 token) reality snapshot (active fuel, held locks, inbox events) directly into volatile prompt context
      - scoping — session id rides every budget frame, audit event, and claim
      - tracking — session counters govern fuel: see budget.md#Fuel-formula; wire, row, and rate costs convert to fuel or sit quota-side: see budget.md#Quotas
      - workspace anchor — CAPCLI_WORKSPACE env var or --workspace flag anchors the project root; runtime state lives in <project>/capcli; cd reliance banned
    - Harness execution boundary
      - execution environment — bash subshell isolated via IPC socket to kernel daemon; direct workspace.db file access blocked
      - execution model — stateless CLI subshell invocation (capcli <noun> <verb>)
      - session persistence — CAPCLI_SESSION env var (override for non-standard harnesses) or workspace.db active context keeps session across turns; Phase 1 sniffing is authoritative in standard harnesses
      - exit contract — process exit codes (0, 2, 3, 4, 5, 6) return status to subshell
      - client boundary — HTTP/WS daemon serving JSON-RPC 2.0 for external harnesses and tools
  - Secrets
    - Vault storage
      - table — secrets system table in workspace.db
      - schema — name unique, value, scope, expires_at, sens: true
      - audit contract — all secret mutations emit vault.set with masked values and SHA-256 fingerprint
      - two-tier secrets — root secrets held in vault; ephemeral egress tokens derived
      - zone 1 blind sandbox — guest address space never allocates credential bytes; guest SDK accepts and passes only opaque vault://<name> URP handles
      - socket jail — guest raw socket connect trapped at OS level, forcing all egress through the kernel proxy: see physics.md#Platform-tier-taxonomy
      - trust floor — kernel authorizer confirms trust >= reviewed before resolving vault://<name> handles: see trust.md#Ladder-laws
      - encryption — AES-256-GCM at rest; cached in memory by daemon or decrypted ephemerally per CLI run
      - ingestion — provisioned via CLI (`capcli sys vault set`), environment variables (`CAPCLI_SECRET_*`), or external client RPC
      - wire echo filter — proxy holds active secret hashes in memory; scans headers and body at wire edge before deserialization; escapes scrubbed to [REDACTED_VAULT_TOKEN] before sandbox or _audit
      - zeroization — in-memory secret buffers zeroized on subshell CLI exit; vault decryption memory zeroize-protected
      - leak protection — plaintext credential exposure in return payloads triggers immediate kill_and_alert (exit 5) and session token revocation
    - Provisioning workflow
      - Lifecycle steps
        - detection — missing secret_ref trips pre-call check before egress
        - auto-refresh — daemon auto-rotates tokens in memory; stateless CLI decrypts root, rotates, and commits updated ciphertext
        - env resolution — kernel checks process env vars (`CAPCLI_SECRET_<NAME>`) before raising suspension
        - injection channels — headless CLI (`capcli sys vault set`), env auto-binding, or external client RPC
        - suspension — headless execution exits with code 3 on missing secrets; interactive sessions pause via ask
    - Egress injection
      - injection point — zone 2 guarded proxy injects Authorization headers at socket edge before TLS; vault://<name> resolves only at this edge; zero plaintext leakage to guest heap or IPC payloads
      - boundary rotation — egress proxy silently refreshes expired bearer tokens
      - references — catalogs reference secret_ref, never plaintext values
      - trust restriction — draft routines denied secret access: exit 2 at pre-flight; floor orthogonal to env matrix; dev-runnable drafts never resolve vault:// handles: see trust.md#Weakest-link-matrix
