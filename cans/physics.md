  - Platform tiering and dual-engine enforcement
    - Platform tier taxonomy
      - tier 1 (hardened) — Linux bare-metal, VPS, Docker (with userns), WSL2
        - sandbox — unprivileged bwrap namespaces; automatically falls back to rootless OCI (crun/podman) or gVisor if host kernel restricts user namespaces
        - network jail — seccomp-bpf filter trapping raw socket connect (syscall 42) across all engines; guest egress routes only via kernel IPC to the socket proxy: see agent.md#Secrets
        - syscall profiles — dynamic seccomp filters per engine:
          - profile_python: allow clone, futex, basic POSIX signals
          - profile_bun_node: allow epoll_create1, epoll_ctl, eventfd2, io_uring_setup
          - profile_binary: allow clone3, futex, rseq, rt_sigreturn
        - trust bounds — all rungs permitted (draft, reviewed, pinned): see trust.md#The-ladder
        - prod host class — tier 1 is the only platform class permitted for --env prod: see trust.md#Weakest-link-matrix
      - tier 2 (virtualized / wasm) — macOS (Darwin), Android (Termux), Windows native
        - sandbox — mandatory microVM (Darwin/Windows: Colima / Lima) or WASM sandbox (Wasmtime; Termux and any tier 2 host) with unmapped socket capabilities
        - network jail — kernel-enforced socket null-routing; cooperative host process execution is Tier 0 (DENIED)
        - trust bounds — dev and sim environments only; pinned routines execute against dev/sim targets; --env prod denied absent a waiver: see trust.md#Weakest-link-matrix
        - tier waiver — --tier-waiver grants one --env prod invocation on a tier 2 host
          - channel — interactive TTY only, typed operator confirmation; headless invocation denied
          - scope — binds to (session id, routine, run); never persisted, never defaulted, never inherited
          - audit — kernel renders a degraded-tier banner and appends tier.waiver_granted audit event carrying the operator identity before dispatch
          - effect — E045_PROD_TIER1_MANDATE does not fire under a valid waiver; pinned rung and E046 still apply
  - Deployment topology
    - dual-axis contract — swarm and federation are separate axes: spokes proxy DB to the Hub; federated workspaces are sovereign peers, each with its own DB and budget: see #Federation-invariants
    - dedicated server — headless Linux host running capcli-daemon under systemd; required for 24/7 background crons, webhooks, and S3 WORM attestations
    - default profile — single-host deployment
      - hub — one Hub daemon; local spokes reach it over unix:// IPC (e.g. /run/capcli/hub.sock)
      - storage — the SQLite writer, the claims system table, and system tables live on this host
      - scope — no network, no overlay, no orchestrator
    - remote profile — explicit opt-in
      - transport — remote spokes and sovereign peers communicate over WireGuard with mTLS; endpoints configured under: see artifacts/policy.yaml#network.transports
      - hub bind — the daemon admin/cockpit surface binds 127.0.0.1:4040 in every profile; the loopback lock covers this surface only
      - mesh bind — remote profile only: the swarm RPC listener binds the mesh interface declared at artifacts/policy.yaml#network.transports with mTLS; spokes dial the hub at that endpoint
      - mechanics — Hub/spoke roles, heartbeat, and reaper mechanics are invariants of the remote profile only: see agent.md#Ephemeral-swarm-identity
      - auth scope — SO_PEERCRED socket authentication applies to local IPC; it never crosses a network boundary
    - ephemeral sandbox node — disposable microVM or container worker; zero-disk state and sync audit ack; identity: see agent.md#Ephemeral-swarm-identity
    - local workstation — ephemeral developer environment; prohibited from serving production endpoints or hosting unattended pinned schedules
    - parity principle — local state mutations and external API egress share equal gate severity
    - local engine — C authorizer and AST parse intercept SQLite commands at prepare time
    - egress engine — optimistic token-bucket quotas slaved to remote headers, secret boundaries, and sim routing intercept network calls
  - Distributed concurrency laws
    - remote authorizer proxy — Hub executes Layer 1 sqlite3_set_authorizer on behalf of spoke ctx.db requests before execution
    - state fencing — OCC state_fence verified at Hub before physical commit: see #Distributed-concurrency-laws (Layer 2)
      - hub evaluation — remote authorizer proxies evaluate Layer 2 OCC fences at the Hub prior to physical commit
    - Layered lock hierarchy — concurrency locking partitions into three non-overlapping timescales; lock layers are distinct from the Two-layer enforcement layers
      - Layer 1 — macro lease
        - storage — the claims system table; business scope measured in minutes
        - purpose — stops concurrent agents touching the same entity
        - identity — strictly (session_id, harness_marker, op_sequence); OS PID binding is banned
        - acquisition — explicit ctx.db.lock(target, ttl) claim or routine manifest auto-claim
        - eviction — background daemon reaps expired claims
        - lifecycle detail: see world.md#claims-lease-lifecycle
      - Layer 2 — meso fence
        - mechanism — OCC state_fence records per-row read versions plus the frame's declared write intent
        - collection — captured during Phase 1 on ctx.db.get and ctx.db.view reads
        - verification — re-verified under SQLite lock during Phase 3 commit
        - read drift — drift on rows the frame only read triggers re-read and re-fence; a suspended frame re-fences at most 3 times, then exits 2 (E061_OCC_DRIFT)
        - write drift — drift on rows the frame wrote or declared in write intent is a write-write conflict: exits 2 (E061_OCC_DRIFT) immediately; zero partial writes
          - purge releases — daemon purge drops the _suspended_tasks row and releases the frame's Layer-1 claims lease
        - commit backstop — commit-time fence re-verified under the Phase 3 SQLite lock stands final
      - Layer 3 — micro lock
        - mechanism — SQLite BEGIN IMMEDIATE via rusqlite
        - lifespan — transaction lifespan strictly <15ms
        - contention — write contention queues up to busy_timeout=5000ms; exhaustion fails closed with exit 2
      - no external calls inside transactions: see action.md#Interior-rules
      - no ws:// calls while holding Layer 1 claims: see action.md#Interior-rules
  - Federation invariants
    - socket authentication — local peer verified via Linux SO_PEERCRED at accept; UID/GID mismatch drops connection instantly
    - bounded re-entry — a workspace may re-enter a call tree exactly once on its original idempotency key; repeated hops replay idempotently: see effect.md#Replay-invariants
    - cycle check — a third entry by one workspace, or re-entry on a fresh key, fails closed with exit 2 (E041_FEDERATION_CYCLE)
    - chain transport — call_chain carries (workspace, idempotency_key) per hop, rides the IPC call envelope, appended per hop, recorded on federation.call_out: see effect.md#Kernel-event-payloads
    - hop ceiling — cross-workspace hops capped at 3; the third hop is a legal re-entry only; breach exits 2
    - lock fence rule: see action.md#Interior-rules
    - transport retry — missing peer socket dials with exponential backoff against the budget configured at artifacts/policy.yaml#network.dial; exhaustion fails closed with exit 4 (E055_FEDERATION_UNREACHABLE)
    - dial budget — fail-closed is invariant; the budget is policy; kernel never restates the number; default 10s total, covering peer cold start
    - secret transit — plaintext secret bytes in federated params scrubbed to [REDACTED_VAULT_TOKEN] at the socket edge; vault://<name> handles pass opaque: see agent.md#Secrets
    - session isolation — caller session never crosses the workspace boundary; callee mints its own session per call: see budget.md#Frames
    - hop/nesting interplay — federated hops count toward call nesting depth; both ceilings enforced, hop ceiling 3 binds first: see #Exit-code-law
    - in-process concurrency — multi-threaded harness subagents (same PID) serialize via OCC state_fence and marker-scoped claims; collision yields via exit 6: see #Exit-code-law
    - network partition fail-closed — lost connection to Hub during sync audit delivery aborts command immediately with exit 5
    - swarm identity and reaper mechanics: see agent.md#Ephemeral-swarm-identity
    - yield and preemption lifecycle: see #Exit-code-law
  - Two-layer enforcement
    - Layer 1: sqlite3_set_authorizer
      - engine — native C callback inside sqlite3_prepare_v2 via rusqlite crate
      - binding — native Rust closure passed directly to rusqlite authorizer
      - scope — access control only (SQLITE_OK, SQLITE_DENY, SQLITE_IGNORE)
      - granularity — 3D action × table × column tuple evaluated per statement
      - intercepted actions
        - tenant isolation — direct SELECT/UPDATE/DELETE on tenant: true tables blocked; access forced through scoped :principal views; ctx.db.mutate asserts row owner == :principal
        - kernel-mediated writes — claims lease insert/delete issued by ctx.db.lock are kernel-internal, not agent SQL; Layer 2 deny_write applies to raw agent statements
        - tenant schema definitions: see world.md#Dual-schema
        - table mutations — read, insert, update, delete allowlists
        - column writes — deny_columns_write protection on immutable keys
        - schema operations — drop, alter, vacuum restrictions
        - engine safety — attach and detach unconditionally denied
        - pragmas — query_only and foreign_keys strictly permitted
        - function allowlist — count, sum, min, max, avg, json_extract, date
        - function denylist — load_extension, writefile, readfile denied
      - compilation — authorizer table compiled from artifacts/policy.yaml
      - ddl trust floors
        - raw DDL — ALTER/DROP/CREATE TABLE denied at authorizer for draft and reviewed principals; denial exits 2
        - legal route — kernel migration pipeline is the sole DDL path: see world.md#Four-phase-state-migration-pipeline
        - vacuum — requires pinned trust; denied unconditionally in prod; executable in dev/sim by pinned callers
    - Layer 1.2: VDBE execution progress & mutation hook
      - engine — sqlite3_update_hook + sqlite3_progress_handler
      - hook checks — counts physical B-Tree row mutations and VDBE byte-code steps during execution
      - mid-flight abort — aborts transaction instantly if mutated row count exceeds the max_rows_affected cap, independent of WHERE clause structure
    - Layer 2: SQL AST check
      - engine — sqlparser crate pre-check (secondary to Layer 1.2 runtime mutation hook)
      - checks
        - parameterization — bound parameters mandatory; raw SQL string interpolation and f-strings fail compilation with exit 3
        - transaction isolation — ctx.api.call in ctx.db.txn blocks rejected
        - federation isolation — ctx.call("ws://...") in ctx.db.txn blocks rejected (exit 3)
        - execution mode — multi-statement raw query strings denied structurally
        - intent gate — mutating writes require valid non-empty causal intent
        - structure — unparseable SQL and schema bypass sequences denied
        - update/delete — bounded writes only: see #Syntax-constraints
        - row bounds — select max 10000, insert max 500, update/delete max 100
        - pagination bounds — OFFSET > 50 denied at prepare-time (exit 2); result envelope contract: see action.md#Shape-constraints
        - deny patterns
          - boolean injections — UPDATE * SET * WHERE * OR 1=1 denied
          - unconditional deletions — DELETE FROM * WHERE NOT EXISTS * denied
          - tautology bypass — boolean bypass attacks (e.g. WHERE 1=1) denied
    - Layer 1.5: prepare-time cross-check
      - engine — sqlite3_prepare_v2 dry-run in test transaction
      - cross-check — compares AST classification against SQLite EXPLAIN
      - opcode trap — OpenWrite detected on statement classified as read denies run
      - discrepancy — unclassified writes (OpenWrite bytecode) trigger denial
    - Unified 3-phase execution engine
      - scope — single execution model for every capability invocation: capcli run, capcli sql, worker tasks
      - Phase 1: static pre-flight — host-side, memory-only; zero physical DB writes, zero network calls
        - harness identity — marker sniffing (PPID/env), token validation, principal check (--as)
        - syntax & AST — SQL/routine parse, binding check; f-strings and interpolation banned
        - complexity ceilings — max 2000 tokens
        - graph integrity — native DFS dependency cycle scan; A → B → A banned
        - lockfile & schema — capcli.lock hash match against current schema
        - static budget headroom — can_invoke_now evaluated against session ceiling
        - refusal — any check fails with exit 3; state untouched
      - Phase 2: sandboxed guest — isolated runner: bwrap on Linux tier 1, microVM/WASM on tier 2
        - isolation — guest address space has zero socket access and zero credential plaintext
        - sequence — Gather (reads) → Compute (pure logic) → Commit (staged ops)
        - IPC actions — discrete ctx.db.*, ctx.api.*, ctx.emit emissions to kernel socket
        - crash — guest crash, unhandled runtime exception, or type violation exits 4; full rollback, state_modified: false
        - yield — proactive yield on low token/fuel floors exits 6; a checkpoint, not an error: see #Exit-code-law
      - Phase 3: kernel commit & audit arbiter — kernel-side physical commit
        - layer 1 authorizer — sqlite3_set_authorizer evaluates action × table × col
        - layer 1.2 mutation hook — row limits enforced on active VDBE bytecode execution
        - atomic commit — physical transaction executed under SQLite BEGIN IMMEDIATE
        - ledger append — _audit event appended with prev_hash link; outbox synced
        - policy denial — authorizer block, check constraint, or budget limit exits 2 with native diagnostic trace
        - kernel panic — sink loss or plaintext secret leak exits 5; row-level corruption: see effect.md#Event-integrity; token revocation
        - exit 0 — single deterministic audit record appended to _audit
      - phase map — Layer 2 AST executes in Phase 1; Layers 1, 1.2, and 1.5 execute in Phase 3
    - Policy vs governance split
      - policy.yaml — behavioral rules: what capabilities may do (verbs)
      - governance.yaml — structural rules: what capabilities may be (nouns)
      - compile phase — compiled at kernel boot; runtime mutation denied
  - Fail-closed stance
    - Anchor principle — default: deny (artifacts/policy.yaml)
    - Boot refusals
      - missing host dependencies — python < 3.11 or git < 2.30 aborts boot on all tiers (exit 3)
      - sandbox missing on tier 1 — absent bwrap automatically falls back to container or microvm runner; aborts boot with exit 3 only if all isolation providers fail
      - sandbox degraded on tier 2 — missing bwrap downgrades to provider=broker with warning
      - clock drift — host clock delta vs NTP > 500ms emits diagnostic warning; internal causal DAG and lease claims bind to CLOCK_MONOTONIC and SQLite sequence IDs
      - unconfigured git identity — missing user.name/email triggers auto-fallback to capcli[bot] or aborts
      - template incompatibility — template min_kernel_version or policy_version mismatch aborts intake (exit 3)
      - template syntax error — routine template failing py_compile validation aborts intake (exit 3)
      - missing configuration — policy.yaml or governance.yaml absent
      - lockfile mismatch in prod — compiled capcli.lock SHA256 mismatch aborts boot with exit 3 in prod; dev and sim auto-recompile if syntax and semantics pass
      - schema drift — un-migrated schema or system_schema hash mismatch aborts boot with exit 3: see world.md#Schema-migration
      - schema integrity — system_schema hash verified at boot: see world.md#Dual-schema
      - driver incompatibility — remote HTTP databases lacking C authorizer refused
    - Runtime refusals
      - secret leak — raw unscrubbed credential bytes detected in guest stdout/stderr streams, routine return payloads, or audit event payloads trigger kill_and_alert (exit 5): see agent.md#Secrets
      - sql errors — unparseable SQL or authorizer errors fail closed
      - anonymous swarm write — mutating action from presence-only or marker-less harness without explicit --session/--by rejected (exit 3): see agent.md#Harness-environment-markers
      - federated caller auth — socket-authenticated ws:// callers use SO_PEERCRED + pinned trust floor, not harness markers: see #Federation-invariants
      - session errors — missing, forged, or expired session token aborts execution (exit 3)
      - latency SLA breach — rehearsal P95 exceeding 70% of timeout ceiling denies promotion
      - ambiguity — unclassified read/write treated as write
      - standalone bypass — routine invocation outside kernel runner exits 3
      - principal missing — scoped view invoked without --as rejected
      - audit sink error — fail-closed sink law: sink write failures deny business writes; undrainable buffer panics: see effect.md#Audit-spine
      - ceiling breach — provider spend ceiling breach rejects with exit 2 before socket dispatch; zero packets, zero TLS handshake: see budget.md#Quotas
      - cadence floor — bucket floor yields exit 6 when wait exceeds 2s or upstream 429 carries Retry-After; shorter waits sleep in-kernel: see budget.md#Quotas
    - Exit code law
      - scope — exit contract binds capcli commands returning CliEnvelope; external tooling defines its own exit contract
      - lint tier — advisory findings exit 0
        - envelope — each finding carried under lint_findings
        - effect — lint findings never deny, never block promotion, never gate execution; they inform the author
      - exit 0 — success with single deterministic audit record appended to _audit; upstream HTTP failures handled gracefully in envelope
      - exit 2 — Phase 3 policy denial; invariant or governance block; state untouched (state_modified: false)
        - domain policy.federation — caller unallowlisted, routine trust < pinned, or cycle detected (E042_FEDERATION_DENIED, E041_FEDERATION_CYCLE)
        - domain db.engine — SQLite check constraints, foreign key violations, busy timeout
        - domain policy.authorizer — C-level table/column write denied
        - domain policy.budget — frame fuel exhaustion, session fuel exhaustion, or call nesting > 5: see budget.md#Frames
        - domain policy.quota — provider spend ceiling breach; hard denial, never yield: see budget.md#Quotas
        - domain policy.migration — offline migration rehearsal breaks the pinned routine contract: see world.md#Migration-safety
        - domain policy.platform — E045_PROD_TIER1_MANDATE: see physics.md#Platform-tier-taxonomy
        - domain policy.trust — draft or reviewed routine in --env prod fails closed at pre-flight (E046_TRUST_VIOLATION); remedy: routine ship <name> pinned
        - domain policy.trust — E047_SECRET_TRUST_FLOOR: see agent.md#Secrets
        - pre-flight matrix checks — E045, E046, and E047 evaluate before dispatch; denial carries exit 2, state untouched
      - exit 3 — Phase 1 static pre-flight refusal: token envelope > 2,000, AST cycle, string interpolation, statically-declared unpaginated payload shape
        - runtime result size — oversized output returns the keyset pagination schema instead of exiting; see action.md#Shape-constraints
      - exit 4 — Phase 2 guest crash; domain routine.runtime; uncaught Python sandbox exception or type crash; transaction cleanly rolled back
        - domain federation.transport — see #Federation-invariants
        - watchdog kill — wall-clock exceeding 300s kills the guest; wall-clock is not fuel
      - exit 5 — Phase 3 kernel panic; domain kernel.panic; sink loss, or raw credential bytes in stdout/stderr streams, return payloads, or audit payloads triggering immediate kill_and_alert; row-level corruption: see effect.md#Event-integrity
        - panic protocol — guest process aborts with exit 5 (kernel.panic); session capability token revoked instantly: see agent.md#Secrets
        - panic protocol — in-memory secret buffers zeroized; security alert event appended to the audit.db ledger: see effect.md#Audit-spine
      - exit 6 — Phase 2 proactive yield
        - yield triggers — cadence wait exceeding 2s, upstream 429 with Retry-After, or priority-class preemption floors: see budget.md#Quotas
        - at yield — Layer 3 physical transactions close immediately; zero open SQLite transactions permitted
        - fence capture — Layer 2 state_fence and resume cursor persist to db://_suspended_tasks
        - lease retention — Layer 1 claims retained so sibling agents cannot steal the task
      - mechanical daemon resumption — when a yielded frame is unblocked by clock refill (reset_at) or human 1-click approval in Cockpit, capcli-daemon executes the pre-compiled guest routine directly in the sandbox to completion; waking or re-prompting the LLM harness for purely mechanical execution is prohibited
      - resume verification
        - lease check — resumption verifies the Layer 1 claims lease is still active and owned by the caller
        - fence check — see #Distributed-concurrency-laws
        - ask predicate — see action.md#The-ctx-contract
      - compile at yield — daemon compiles the guest routine into a standalone artifact at yield time; resumption runs that artifact to completion without waking the harness
      - result delivery — daemon posts completion results to the sensory inbox; harness surfaces them at the next turn-zero overview: see interface.md#CLI-surface
      - preemption yield — worker spot/container SIGTERM maps directly to exit 6; traps execution, flushes cursor checkpoint, parks frame to db://_suspended_tasks: see #Exit-code-law
      - frame abort — run abort <frame_id> purges the _suspended_tasks resume target, releases the OCC state_fence and the frame's Layer 1 claims, writes an audit event; the frame never resumes
      - drift recovery — E061_OCC_DRIFT on a still-suspended frame (read-drift fence exhaustion): abort the drifted frame (run abort <frame_id>) before re-running the routine
        - direct re-run hits the retained claims lease (claim_held)
        - write-drift needs no abort — the purge already released the lease; re-plan and re-queue directly
      - state rollback law — non-zero exits guarantee state_modified: false; any partial commit is a critical kernel bug
    - Diagnostic output law
      - engine — native terminal diagnostics rendered procedurally via zero-dependency text formatter
      - data contract — all commands return `CliEnvelope<T>`: { context, exit_code, state_modified, data, diagnostic, audit_op }
      - success affordances — typed next actions on exit 0: see interface.md#CLI-surface
      - layout archetypes — human output maps to exactly 4 procedural formats:
        - archetype A (diagnostic) — exits 2, 3, 4, 5, 6; renders header, failing span with carets (`^^^^`), and indented metadata block
        - archetype B (tree) — hierarchical DAGs (`sys trace`, `inspect`); renders unicode branches (`├──`, `└──`, `│`)
        - archetype C (receipt) — exit 0 key-value records; renders aligned pairs separated by `─` dividers
        - archetype D (document) — sliced outputs, keyset envelopes, help; renders divider-separated body slices with pagination cursor state
      - machine envelope — `--json` returns raw serialized `CliEnvelope<T>`
      - payload redirection — `--out <path>` writes payload to disk; stdout returns <30 token receipt
      - shell escaping defense — all arguments accept `@<path>` or `@-` (stdin)
      - typography rules — table pipes (`|`) banned; tree characters locked to `├──`, `└──`, `│`; divider locked to `─`
      - buffer isolation — stdout/stderr unlogged; effect engine hashes canonical JSON exclusively
    - Break-glass paths
      - recovery shell: see recovery.md#Emergency-recovery-mode
      - diagnostic check — sys doctor --boot-check verifies boot without daemon
      - validation check — rule validate runs in CI prior to commits: see cicd.md#Pull-request-gate-pipeline
  - Raw SQL rules
    - Baseline stance
      - exploration — raw SQL permitted for data exploration
      - abstractions — ORMs and custom query builders banned
      - gate interception — prepare-time checks enforce physics: see #Layer-1:-sqlite3_set_authorizer
    - Syntax constraints
      - parameterization — positional or named bindings mandatory; interpolation banned
      - write limits — UPDATE and DELETE require WHERE targeting a specific primary key or bounded predicate; unbounded predicates denied at AST parse; mutation hook aborts past 100 rows
      - transaction wraps — raw writes execute inside explicit transactions
      - statement count — multi-statement execution denied
    - Hard denials
      - ddl execution — alter/drop denied at authorizer for draft and reviewed principals (exit 2); vacuum floors: see #Layer-1:-sqlite3_set_authorizer
      - trigger injection — agent-created triggers denied at authorizer
      - extension loading — load_extension and file functions denied
      - system table writes — direct updates to _audit, agents, claims denied
  - Bulk operations
    - Chunking model
      - loop pattern — agent loops bounded chunks via ctx.db.execute
      - transaction scope — each chunk forms independent transaction and audit event
      - execution bounds — max rows per chunk: see artifacts/policy.yaml#query
    - Pre-flight checks
      - count query — sql --count mandatory before mass updates
      - environment exemptions — dev and sim waive mandatory pre-counts
    - Trust thresholds
      - prod confirmation — bulk updates in prod require approval above 10 rows
      - bulk minimum — trust >= reviewed: see artifacts/policy.yaml#query
      - human threshold — writes exceeding row caps require confirmation

    - Boundary isolation
